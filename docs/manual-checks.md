# 手動確認 — pi-switch

自動検証の対象外の確認項目と手順です。

## 手動確認項目

前提: TUI の Pi セッションで確認します。

1. `/switch` の Tools で `grep` が `○` と表示されること（Pi の既定で無効）。Space を 1 回押すと `g:on` が付き、次のターンのモデルのツール一覧に `grep` が現れること。
2. さらに Space を押して `off`、もう一度押して継承（バッジなし）に戻ること。継承に戻すと、`grep` が Pi の既定（無効）に戻ること。
3. スキルを `off` にし、システムプロンプトの `<available_skills>` から消えること。ただし `/skill:<name>` は実行できること。
4. Packages で `npm:pi-exa` を `off` にし、由来ツールとスキルがまとめて消えること。Project で `exa_search` だけを `on` にし、1 つだけ戻ること。
5. Global と Project の状態がそれぞれのファイルに保存され、再起動後も維持されること。
6. Global で `on` にしても Project が `off` のままのとき、警告が表示され、Project の `off` が効き続けること。
7. 未信頼のプロジェクトで Project ファイルが読まれず、書き込みが拒否されること。
8. 壊れた設定ファイルを置いても設定が空になるだけで、ファイルが破壊されないこと。
9. Sections で `docs` を `off` にし、次のターンのシステムプロンプトから `<docs>` が消えること。セッションファイルには残ること。継承に戻すと復帰すること。
10. 未信頼のプロジェクトで Project ファイルのセクション設定が読まれず、書き込みが拒否されること。
11. MCP で `mcp__docs` を `off` にし、そのサーバーの `direct` ツールが次のターンのツール一覧から消えること。継承に戻すと復帰すること。サーバーへの接続は維持されること。
12. MCP サーバーがセッション開始後に接続しても、`off` のサーバーの `direct` ツールが最初のリクエストから無効になっていること。
13. Sections の行に説明が表示されること。ビルトインは固定文、`knowledge_index` などは本文の先頭行になること。
14. ←→ で種類が切り替わり、Packages の行で Space を押すと配下の個別項目が消えること。
15. PageUp / PageDown / Home / End で選択が端または 1 ページ分動くこと。
16. version 1 のファイル（`disabled` / `enabled`）を読むと、同じ意味で動くこと。次に変更すると version 2 で書き直されること。
