# MCP サーバーは packages のソースグループとして露出を切り替える

- 状態: 採用
- 日付: 2026-10-06
- 対象: `/switch` の MCP 切替と、MCP サーバーのツール適用

## 背景

MCP サーバーのツールは名前空間 `mcp__<server>` の下にまとまって登録され、数十件になることがあります。既定の exposure は `codemode` で、`direct` にするとモデルへ直接宣言されます。個別ツールを1つずつ切り替えるのは手間で、コンテキストを節約したい単位はサーバーです。

pi-switch で MCP を一括切替する方法の候補は3つありました。

- MCP サーバーを既存の `packages` の名前として扱う
- トップレベルに `mcp` キーを新設する
- Pi の `mcp.json` を書き換えてサーバーを無効化する（`/mcp` と同じ）

## 決定

- MCP サーバーは、ツールの namespace 名 `mcp__<server>` をそのまま `packages` の名前として使います。値は `on` / `off` です（[0007](0007-tri-state-values-and-project-precedence.md)）。
- ピッカーには Packages と Tools の間に MCP セクションを新設し、1サーバー = 1行で表示します。行のトグルはグループキーだけを書き、子ツールを列挙しません。個別ツールは Tools 行で調整します。
- 切替は露出だけで、サーバーへの接続は維持します。アイドル状態にしても MCP プロセスを止めません。対象は `direct` / `model-only` のツールで、`codemode` / `deferred` の実行候補は Pi が別に管理するため対象外です。
- MCP サーバーは `session_start` より後に接続するため、pi-switch は登録ツールの変化を `before_agent_start` で検知し、そのリクエストの前に無効状態を適用します。無効化で外したツール名はセッション中だけ保持し、有効化で復元します。

## 理由

- `packages` は「ソース単位の一括」の仕組みです。MCP サーバーはツールのソースであり、解決規則・スコープ上書き・バッジをすべて再利用できます。設定形式（キー）を増やさず、値の意味も変えません。
- トップレベルの `mcp` キーは `sections` と同じく旧版が保存できますが、一括の種類を増やすほどの差がありません。解決規則が1つ増える分だけ複雑になります。
- `mcp.json` の書き換えと接続の切断は Pi 本体の `/mcp` の役割です。pi-switch が同じ書き込みを行うと二重管理になり、reload と接続待ちのコストを持ち込み、露出だけを止める原則を失います。
- `session_start` の時点では MCP の `direct` ツールはまだ登録されていません。起動時の有効集合だけを基準にすると、後から接続したツールを無効化できず、有効化のときは逆に集合から落としてしまいます。登録の変化を検知して適用する必要があります。

## 帰結

- 設定の `packages` には、npm・git などのソースと MCP サーバーの `mcp__<server>` が同じリストに入ります。README の名前表と解決規則に明記します。
- MCP 行は子ツールを列挙しないため、`g:off` などのバッジは付きません。`●` / `○` が実効状態を示します。個別ツールを無効化すると、そちらにはバッジが付きます。
- 起動時に有効でないツールは、設定が `on` のときに有効になります（[0007](0007-tri-state-values-and-project-precedence.md)）。
- `codemode` / `deferred` のツールは、Pi が実行候補を有効集合とは別に管理するため、有効集合の操作では無効化できません。pi-switch が制御できるのは `direct` / `model-only` の露出だけです。露出そのものの変更は Pi の `/mcp` を使います。

## 代替案

| 代替 | 却下理由 |
|---|---|
| トップレベル `mcp` キーを新設する | 設定形式と解決規則が増える割に、`packages` の再利用で得られるものと同じ結果になる |
| `mcp.json` を書き換えてサーバーを無効化する | Pi 本体の `/mcp` と二重管理になり、reload が必要。接続を切るので「露出だけを止める」原則に反する |
| 全 MCP サーバーを1行で一括切替する | サーバーごとの粒度が失われ、後から追加されたサーバーを一括行が覆わない。まずはサーバー単位から始める |
| 非 `direct` のツールを一覧から除外する | 既存のツール一覧の意味が変わり、`/switch` で見えなくなるツールが増える。別の決定として扱う |
