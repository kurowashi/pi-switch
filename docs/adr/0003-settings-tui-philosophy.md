# 列挙型の大きな設定に限り TUI を採用する（共通哲学 原則7 の改訂）

- 状態: 採用
- 日付: 2026-10-05
- 対象: `/switch` TUI と、プラグイン群共通の PHILOSOPHY.md 原則7

## 背景

共通哲学 原則7 は「設定を変更するコマンドは、実測した変更頻度が高い設定にだけ、引数で完結する形で追加します。設定 UI は採用しません」と定めていました。
pi-switch の設定対象は、インストール済みのツール・スキル・パッケージという列挙型で、数十件に及びます。対象は Global と Project の2層にまたがり、パッケージ単位の一括指定と個別の有効化が同じファイルで交差します。
これを引数コマンドで表すと、対象名の補完と層の指定が必須になり、変更のたびに2ファイルの解決規則をユーザーが頭の中で適用することになります。

## 決定

共通哲学 原則7 を改訂し、次の条件を満たす場合に限り TUI を採用できるようにします。

- 対象が列挙型で数が多い
- スコープや層をまたぐ組み合わせの編集を引数で表すのが現実的でない

改訂後も、設定ファイルが正であること、解決済み状態を確認できること、引数で完結する形を既定とすることは変わりません。
変更は全10コピーの PHILOSOPHY.md に同時に適用します。

## 理由

- 原則7 自身が「解決できない問題が出たときだけ見直す」と定めており、このケースが該当します。
- pi-switch の TUI はファイルを正のまま扱い、解決済み状態の表示と編集を同じ画面で行います。原則7 の目的（隠れた状態を持たない）に反しません。
- プロジェクト固有の例外を積み上げる代わりに共通哲学を直すことで、「各リポジトリの DESIGN.md は共通哲学を土台にする」という関係を保てます。

## 帰結

- PHILOSOPHY.md の変更は全リポジトリの同時更新が必要です。この日付のコミットで pi-plugins 配下の全リポジトリを更新します。
- TUI を持つ将来のプラグインは、同じ条件を DESIGN.md で説明する必要があります。
- 引数コマンドは将来必要になった時点で、変更頻度の実測を添えて追加します。現時点では追加しません。

## 代替案

| 代替 | 却下理由 |
|---|---|
| 引数コマンド主体にする（`/switch disable tool <name> --global`） | 数十件の列挙と2層の交差を引数で表すのは現実的でなく、ファイルを手で編集するのと同等の負担が残る |
| pi-switch だけを例外として DESIGN.md に記録する | 共通哲学が「プロジェクト単位の例外を積み上げない」と定めており、定期確認の対象になる |
| TUI を表示専用にし、変更はファイル編集に限る | ユーザー要件（TUI で設定可能）を満たさない |
