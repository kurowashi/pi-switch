# 設定値は on / off / 継承の 3 値にし、Project を Global より優先する

- 状態: 採用
- 日付: 2026-10-16
- 対象: 設定ファイルの値の形式、解決規則、`/switch` の Space の動作、ツールの既定表示
- 置き換え: [0002](0002-two-file-scope-layering.md) の解決規則、[0006](0006-startup-inactive-tools-shown-as-configured.md)

## 背景

v1 の設定は `disabled` / `enabled` の 2 つのリストで、解決は 4 段の逐次適用でした（Global の disabled → Global の enabled → Project の disabled → Project の enabled）。

このため、次の問題がありました。

- 「Global で有効、Project で無効」は、どちらのリストに書いたかで読み手の理解が変わります。Project の `disabled` が Global の `enabled` に勝つ理由を、規則を辿らずに読めません。
- 同じ名前が 2 つのリストに現れうるため、ファイルを見ただけでは最終状態が分かりません。
- Space は 2 状態の反転でした。起動時に Pi が無効にしているツール（`grep` など）は、一覧で `●` と出ても有効集合に入らず、有効化に 2 回押す必要がありました。
- 一覧の `●` は設定から導いており、Pi の実際の有効集合とは一致しませんでした。ADR 0006 はこれを README で説明する方針でした。

## 決定

- 設定の値は `"on"` / `"off"` の 2 値です。項目が無いことを「継承」とします。
- Space / Enter は 継承 → on → off → 継承 の順に変えます。継承に戻すと項目を削除します。
- 1 つの対象の値は、Project の個別項目 → Project のパッケージ項目 → Global の個別項目 → Global のパッケージ項目 の順で最初に見つかったものを使います。どこにも無ければ既定です。
- 既定は次のとおりです。
  - ツール: セッション開始時に Pi が有効にしていたかどうか。pi-switch は初めて触れた時点の状態を記録します。
  - スキル・パッケージ・MCP サーバー・プロンプトセクション: 有効。
- 既定は設定ファイルに書きません。Pi の有効集合は設定ではなく、起動時の観測値です。

## 理由

- 値を 2 値にすると、同じ対象に対する指定が 1 つの場所に集まり、読み手は「その対象の値」だけを見れば済みます。
- 解決を「Project、次に Global」の 2 段にすると、規則の数が層の数と同じになります。旧 4 段の「後の層が勝つ」は、Project の `disabled` と Global の `enabled` の関係を読み手に推論させていました。
- 継承を値として持つと、「Pi の既定に任せる」と「明示的に off にする」を区別できます。`grep` を `○` と表示し、Space 1 回で有効にできるため、表示と効果の差がなくなります。
- ツールの既定を Pi の起動時の集合から取るのは、Pi が決めた既定を pi-switch が上書きしないためです。設定に既定を書けば、Pi の `defaultTools` の変更に追従できなくなります。

## 帰結

- 旧形式を読み込んだ結果は、同じ対象に対して旧解決と同じ効果を持ちます。ただし読み込み後に書き直すと、値の形式は 2 値に変わります（[0008](0008-migrate-v1-config-with-removal-deadline.md)）。
- 「Global で `on`、Project で `off`」は、Project が勝つため無効のままです。Global で `on` にしたときは、警告を表示します。
- 設定を手で書くときは、継承を表すために項目を削除します。`"inherit"` のような値は受け付けません。
- Pi の既定が変わると、継承のツールの表示も変わります。設定ファイルの内容は変わりません。
- [0005](0005-mcp-servers-as-package-groups.md) の「起動時に有効でないツールは `/switch` で明示的に有効化したときだけ有効になる」は、この ADR により「既定に従い、`on` で有効になる」に読み替えます。

## 代替案

| 代替 | 却下理由 |
|---|---|
| v1 の 4 段の逐次適用を残し、表示だけ直す | 解決を読むための推論が残り、表示と解決の規則が別々になる |
| 2 値のみ（継承なし） | 未設定のツールの既定を書く必要があり、Pi の既定変更に追従できない。新しいツールはすべて明示的な設定を要する |
| 既定を設定ファイルに書く | 既定が設定の一部になり、Pi の `defaultTools` の変更と食い違う |
| 表示を有効集合から導き、設定を捨てる | 設定が正であるという原則（DESIGN.md）に反する。設定と有効集合の二重の正になる |
