# スキル無効化はモデルへの露出だけを止める

- 状態: 採用
- 日付: 2026-10-05
- 対象: スキルを無効にしたときの意味

## 背景

スキルを「無効」にする方法は2つあります。システムプロンプトのスキル一覧から外す方法と、Pi の resource settings を書き換えて読み込ませない方法です。前者は即時、後者は reload が必要です。pi-scope はどちらを既定にするか決める必要がありました。

## 決定

無効化はシステムプロンプトのスキル一覧から外すだけとし、`/skill:<name>` の明示実行は残します。Pi の settings は書き換えません。

## 理由

- 誤発火とコンテキスト消費の防止が目的であり、明示実行を禁じる必要はありません。
- 即時反映を保てます。reload はセッションの流れを切ります。
- 設定の正が pi-scope のファイル1箇所に収まり、Pi の settings と二重管理になりません。
- 完全に消したい場合は、スキルの提供元（パッケージやディレクトリ）を外すという Pi 本来の手段があります。

## 帰結

- 無効にしたスキルも `/scope` の一覧には表示され続けます。状態で区別します。
- ユーザーが「無効にしたのに `/skill:` が使える」と感じる可能性があるため、README の動作表で明記します。

## 代替案

| 代替 | 却下理由 |
|---|---|
| Pi の resource settings で完全にアンロードする | reload が必要になり、即時反映の原則を失う。書き込み API も公開されていない |
| 露出とアンロードの2軸を提供する | 設定と UI が倍になり、v0.1 の利用者に必要ない |
| 何もしない（Pi 標準の `disable-model-invocation` を手で編集する） | 編集対象が分散し、スコープ単位の切り替えができない |
