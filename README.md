# pi-switch

Pi に拡張を入れると、その拡張のツールとスキルがモデル向けの一覧にすべて加わります。使わないものもコンテキストを消費し、関係のないスキルが誤って呼ばれることがあります。MCP サーバーのツールやシステムプロンプトのセクションも同じく一覧を占めます。pi-switch は、モデルに見せる範囲を `/switch` で切り替えます。

- 切り替えの粒度: ツール個別・スキル個別・パッケージや MCP サーバーの一括・プロンプトセクション個別
- 保存先: Global（ユーザー全体）と Project（リポジトリ単位）の 2 つの JSON ファイル
- 反映: 拡張の再読み込みは不要で、次のリクエストから反映されます

```
$ /switch

pi-switch  [Global] Project
filter: type to search
  Packages
  ● npm:pi-exa  2 tools · 1 skill
  MCP
  ● mcp__docs  3 tools  Project documentation
  Tools
❯ ● exa_search  npm:pi-exa
  ○ exa_request  npm:pi-exa
  ● mcp__docs__search  mcp__docs
  Skills
  ○ ui-review  npm:pi-skills
  Sections
  ● docs
  ○ knowledge_index
space toggle · tab scope · esc close        5/8 tools · 3/5 skills
```

表示例です。実際の行は選択中のスコープと登録されているリソースによって変わります。

## 使い方

1. `/switch` を実行します。
2. ↑ / ↓ で行を選び、Space または Enter で切り替えます。
3. Tab で編集するスコープを Global と Project の間で切り替えます。

切り替えは選択中のスコープのファイルに保存され、すぐに反映されます。

一覧の ● / ○ は、全層を適用した設定の状態です。モデルに届いているかどうかは表しません。
Pi は既定では `read` / `bash` / `edit` / `write` だけを起動時に有効にします（`defaultTools` や `--tools` の指定で変わります）。例えば `grep` は既定の有効集合に含まれないため、起動直後は ● と表示されても、モデルには届いていません。
この場合、Space を 1 回押すと ○ になり、モデルへの変化はありません。もう 1 回押すと ● になり、有効になります。

## インストール

```bash
pi install git:github.com/kurowashi/pi-switch
```

ref を固定する場合は `pi install git:github.com/kurowashi/pi-switch@<tag|commit>` を使います。

ローカルの作業コピーを使う場合は次のとおりです。

```bash
pi install /path/to/pi-switch
```

インストールせずに読み込む場合は次のとおりです。

```bash
pi --extension /path/to/pi-switch/src/index.ts
```

開発と検証は Pi 1.0.3 で行っています。それ以外のバージョンでの動作は確認していません。

## 設定

設定ファイルは 2 つです。後の層が前の層を上書きします。

| ファイル | 対象 | 読み書きの条件 |
|---|---|---|
| `<agent dir>/pi-switch.json`（既定は `~/.pi/agent/pi-switch.json`） | Global | 常に読み書きする |
| `<cwd>/.pi/pi-switch.json` | Project | プロジェクトが信頼されているときだけ読み書きする |

`<agent dir>` は環境変数 `PI_CODING_AGENT_DIR` で変更できます。`.pi` の部分は Pi の `piConfig.configDir` に従います。

```json
{
  "version": 1,
  "disabled": {
    "packages": ["npm:pi-exa"],
    "skills": ["pdf"]
  },
  "enabled": {
    "tools": ["exa_search"]
  },
  "sections": {
    "disabled": ["docs"]
  }
}
```

この例は [examples/pi-switch.example.json](examples/pi-switch.example.json) にもあり、そのままコピーして使えます。

### キー

| キー | 型 | 意味 |
|---|---|---|
| `version` | number | 設定の版。`1` だけを受け付けます。省略すると `1` として扱います |
| `disabled.tools` / `disabled.skills` / `disabled.packages` | string[] | 無効にする対象の名前 |
| `enabled.tools` / `enabled.skills` / `enabled.packages` | string[] | 無効化を打ち消して有効に戻す対象の名前 |
| `sections.disabled` / `sections.enabled` | string[] | 無効にする／有効に戻すプロンプトセクションの名前 |

プロンプトセクションは `sections` キーにだけ書きます。`disabled` / `enabled` マップには書きません。`sections` は省略できます。省略した場合は両方とも空として扱います。
上の表にないトップレベルフィールドは読み飛ばします。保存し直すときもそのまま残すため、他のツールが書いた項目は消えません。

### 対象の名前

| 種類 | 名前の例 | 名前の由来 |
|---|---|---|
| ツール | `exa_search` | `pi.getAllTools()` が返すツール名 |
| スキル | `pdf` | スキルの `name` |
| パッケージ | `npm:pi-exa` | ツールやスキルの `sourceInfo.source` |
| MCP サーバー | `mcp__docs` | ツール名の namespace `mcp__<server>` |
| プロンプトセクション | `docs` | `context_with_system` のリクエストに現れたセクション名 |

- npm のソースは版を除いて書きます。`npm:pi-exa@1.2.3` は `npm:pi-exa` として扱います。
- npm 以外のソース（例: `git:…`）は、`sourceInfo.source` をそのまま使います。
- サーバー名に `-` を含む MCP サーバーは、`-` を `_` に置き換えた名前を書きます。例: サーバー `my-docs` は `mcp__my_docs` と書きます。
- コマンドだけを提供し、ツールもスキルも出さないパッケージは一覧に出ません。その名前を書いても効果はありません。
- 接続していない MCP サーバーは一覧に出ません。
- プロンプトセクションの名前は、まだリクエストに現れていなくても書けます。書いた名前がリクエストに現れるまでは効果がありません。

### 解決規則

すべての対象は、初期状態で有効です。次の順に適用します。

1. Global の `disabled` に含まれる → 無効
2. Global の `enabled` に含まれる → 有効
3. Project の `disabled` に含まれる → 無効
4. Project の `enabled` に含まれる → 有効

- どのリストにも含まれない対象は有効のままです。
- プロンプトセクションは、Global の `sections.disabled` → `sections.enabled` → Project の `sections.disabled` → `sections.enabled` の順に解決します。
- パッケージや MCP サーバーの指定は、そこに由来するツールとスキルすべてに効きます。個別の `enabled` は、パッケージの `disabled` より後に適用されます。そのため、パッケージを無効にしたうえで 1 つだけ有効に戻せます。
- Global で無効にしたものを、特定のプロジェクトだけ有効に戻せます。
- Project で無効にしたものを Global で有効にすることはできません。Project の無効が残るときは、切り替え時に警告を表示します。
  - このとき Global ファイルには `enabled` の記録が残るため、Global の行には `g:on` が出ます。このプロジェクトでは無効のままです。Project で無効にしていない他のプロジェクトでは有効になります。

### 読み込みの失敗

- JSON が壊れている、または既知のフィールドの型が違う場合、そのファイルの内容を空として扱い、警告を 1 回だけ表示します。
- 壊れたファイルは上書きしません。トグルは拒否して理由を表示します。修復するか削除すると、次の読み込みから反映されます。
- 信頼されていないプロジェクトのファイルは読みません。`/switch` の Project スコープは編集できず、理由を表示します。

## 仕組み

pi-switch が変えるのは「モデルへの露出」だけです。拡張は読み込んだままで、コマンドも使えます。

| 対象 | 無効にしたときの効果 | 反映のタイミング |
|---|---|---|
| ツール | モデルへの宣言から外れる。対象は Pi の exposure が `direct` / `model-only` のツールだけ | 次のリクエストから |
| スキル | システムプロンプトのスキル一覧から外れる。`/skill:<name>` の明示実行は残る | 次のリクエストから |
| パッケージ | 由来するツールとスキルをまとめて無効にする | 次のリクエストから |
| MCP サーバー | 由来する `direct` / `model-only` のツールをまとめて無効にする。サーバーへの接続は維持する | 次のリクエストから |
| プロンプトセクション | 送信するシステムプロンプトからそのセクションを取り除く。セッションの履歴は変えない | 次のリクエストから |

### ツールの適用

- pi-switch はツールの有効集合を、セッション開始時・切り替え時・新しく登録されたツールを検知した次のリクエストの前に適用します。
- 登録の変化がないターンでは、他の拡張がツールの有効状態を変えても pi-switch は再適用しません。
- 無効にしたツールは、pi-switch が外した記録から有効に戻します。記録のないツールは有効にしません。起動時に Pi が有効にしていないツールは、Space を 2 回押すまで有効になりません（[使い方](#使い方)）。

### MCP サーバー

- MCP サーバーは `session_start` より後に接続します。そのため、pi-switch は登録されたツールの変化を検知し、次のリクエストの前に無効状態を適用します。
- 無効化は露出だけを止めます。サーバーへの接続は維持します。切断は Pi の `/mcp` で行います。
- `codemode` / `deferred` のツールは、有効集合の外でも実行候補になります。pi-switch の無効化はこれらを実行候補から外しません。

### スキル

- スキルはリクエストごとに、システムプロンプトのスキル一覧から外します。
- 無効化は `/skill:<name>` の明示実行を止めません。

### プロンプトセクション

- セクションは、すべての拡張がプロンプトを組み立てた後、リクエストを送る直前に取り除きます。
- セッションの履歴には残るため、コンパクションやセッションの再開の結果は変わりません。
- 一覧は、ビルトインの 8 セクション（`preamble` / `tools` / `rules` / `docs` / `addendum` / `project_context` / `skills` / `cwd`）と、そのセッションのリクエストに現れた名前を合わせたものです。
- セクションの説明は、ビルトインは固定の文です。他の拡張が注入したセクションは、最初に観測した本文の先頭行（見出し記号を除く）を使います。説明にできる行がなければ、説明は表示されません。
- 無効化の前に観測するため、無効化されたセクションも一覧に残ります。

### 設定の読み込みと書き込み

- 設定は、セッション開始時、`/switch` を開いたとき、切り替える直前に読み込みます。
- 手でファイルを編集した場合、`/switch` を開き直すと反映されます。
- 切り替えの直前にはファイルを読み直します。ピッカーを開いている間に行った外部の編集を上書きしません。
- 保存は一時ファイルを作ってから置き換えます。一時ファイルは残りません。

## コマンド

| コマンド | 動作 |
|---|---|
| `/switch` | 設定を操作するピッカーを開きます。引数は取りません |

- 引数を付けると、引数を受け付けないことを警告します。
- TUI モード以外（print / JSON モードなど）では、ピッカーを開かずにエラーを表示します。

### キー

| キー | 動作 |
|---|---|
| ↑ / ↓ | 選択を移動する |
| PageUp / PageDown | 選択を 14 行分移動する。先頭と末尾で止まる |
| Home / End | 先頭と末尾の選択行へ移動する |
| Space / Enter | 選択行を編集中のスコープで切り替える |
| Tab | 編集するスコープを Global と Project の間で切り替える |
| 文字入力 | 名前・パッケージ名・説明で絞り込む |
| Backspace / Delete | 絞り込みを 1 文字消す |
| Ctrl+U | 絞り込みを全部消す |
| Esc / Ctrl+C | 絞り込みがあれば消す。なければピッカーを閉じる |

- Project が信頼されていない場合、編集スコープが Project のときは Space / Enter で切り替えられません。理由を表示します。
- パッケージの行は、実効状態が「有効」のときは無効にし、それ以外（一部無効・全部無効）のときは有効にします。
- MCP の行は、サーバー単位の名前だけを設定に書きます。個別のツールは Tools 行で調整します。

### 行の並び

行は Packages → MCP → Tools → Skills → Sections の順に並びます。対象がない種類の見出しは表示しません。

### 表示

| 表示 | 意味 |
|---|---|
| `●` | 実効状態が有効 |
| `○` | 実効状態が無効 |
| `◐` | パッケージ・MCP の行で、由来するリソースの一部だけが無効 |
| `g:on` / `g:off` | Global ファイルがその対象を直接記録している |
| `p:on` / `p:off` | Project ファイルがその対象を直接記録している |

`●` / `○` は全層を適用した結果です。`g:` / `p:` は、各ファイルが直接記録している内容です。パッケージや MCP のリソースは、パッケージや MCP の行で記録されるため、個別の行にはバッジが付かないことがあります。

## 制限

- 拡張を読み込み解除しません。pi-switch が止めるのはモデルへの露出だけです。
- 一覧の `●` は設定の状態です。モデルに届いているかどうかは、[使い方](#使い方)の注意に従います。
- `hidden` の露出のツールは一覧に出ません。Pi がモデルへ宣言しないためです。
- 一覧に出ないツール名（Pi の `getAllTools()` が返さない名前）は、pi-switch の対象外としてそのまま残します。
- スキルは名前単位で扱います。同じ名前のスキルが複数ある場合、衝突を表示しません。
- 信頼されていないプロジェクトでは、Project の設定を読み書きしません。
- 検証は Pi 1.0.3 で行っています。それ以外のバージョンでの動作は確認していません。
